PTS - Phoenix Talk Skill 설명:
PTS는 Phoenix Talk Skill의 약자입니다. 사용자가 좋은 샘플, 원고, 보고서, 대본, 프롬프트, 체크리스트, 문체 기준을 제공하면 그 안에 들어 있는 사고방식, 구성 순서, 품질 기준, 금지사항을 분석해서 봇이 재사용할 수 있는 스킬 후보로 정리하는 방식입니다. 화면 조작보다 결과물의 완성도와 판단 기준이 중요한 업무에 적합합니다. PTS의 목표는 봇이 한 번 본 샘플을 그대로 흉내 내는 것이 아니라, 좋은 결과가 나오는 원칙을 skills, examples, checklist로 분해해 다음 작업 품질을 높이는 것입니다.

PTS로 정리할 때 반드시 포함할 내용:
- 대상 봇과 스킬 이름
- 좋은 샘플 또는 참고 자료의 핵심 특징
- 원하는 결과물 형식과 문체 기준
- 구성 순서, 판단 기준, 품질 체크포인트
- 나쁜 결과 예시와 금지사항
- updater로 반영할 skills/examples/checklist 후보

Genesis Bot, 이 업무를 PTS 방식으로 스킬업하고 싶어.

대상 봇:
좋은 샘플 또는 참고 자료:
내가 원하는 결과물:
문체 또는 구성 기준:
반드시 지켜야 할 규칙:
나쁜 결과 예시 또는 피해야 할 방식:

이 내용을 바탕으로 봇이 재사용할 수 있는 스킬 후보안을 만들어줘.
후보안에는 skills, examples, checklist로 나누어 반영할 내용을 포함해줘.

* 봇별 설명
=============================================
Genesis Bot
비서실장 봇

전체 봇을 지휘하고 작업 구조를 잡는 총괄형 봇입니다. 메시지를 받으면 “무엇을 누구에게 맡길지”를 결정하는 관점으로 대응하면 좋습니다.

이 봇 설명 복사
봇 성격
전체 봇을 관리하고, 작업 지시문·자동화 흐름·서비스 구조를 정리하는 지휘형 봇입니다.
메시지에서 보는 핵심
전체 작업 순서, 봇별 업무 분장, 자동화 설계, 서비스/플랫폼 구조가 핵심입니다.
유저의 역할
목표와 우선순위를 알려주고, Genesis가 다른 봇에게 나눠 줄 지시문을 검토하는 승인자 역할을 합니다.
읽는 순서: 먼저 메시지 종류를 확인하고, 그 다음 유저 역할을 읽은 뒤, 쉬운 답장 예시를 그대로 보내거나 내 상황에 맞게 한 줄만 바꾸면 됩니다. 학습 강화와 스킬 강화는 반드시 업데이트 파일과 복사용 명령문까지 확인합니다.
준비 완료 메시지
유저 대응
메시지
전체 봇 지시문, 자동화 프로그램, 서비스 구조 설계처럼 큰 그림 중심의 작업 메뉴가 나옵니다.
유저 역할
오늘의 전체 목표를 말하고, 어느 봇부터 움직일지 결정합니다.
쉬운 답장
오늘 AI 강의 홍보 페이지를 만들 거야. Power, Design, Writer에게 나눠 줄 작업 지시문부터 만들어줘.
30분 미시작 메시지
유저 대응
메시지
봇은 준비됐지만 유저가 시작하지 않았으므로, Genesis가 첫 작업 후보를 먼저 제안합니다.
유저 역할
제안 중 하나를 고르거나, 지금 필요한 전체 지휘 업무로 바꿔 줍니다.
쉬운 답장
진행. 오늘 할 일을 5개 봇에게 어떻게 나눌지 업무 분장표로 만들어줘.
3시간 요약 메시지
유저 대응
메시지
최근 파일, 로그, 작업 흐름을 보고 전체 프로젝트가 어디까지 왔는지 다시 정리합니다.
유저 역할
이어서 할지, 멈출지, 우선순위를 바꿀지 결정합니다.
쉬운 답장
요약 기준으로 다음 3단계 실행 계획을 다시 짜줘. 먼저 해야 할 일부터 정렬해줘.
오전 7시 트렌드 메시지
유저 대응
메시지
AI 에이전트, 자동화, 서비스 플랫폼 관련 최신 흐름을 찾아 업무 아이디어로 바꿔 제안합니다.
유저 역할
트렌드를 단순히 읽지 말고, 우리 수업·서비스·자동화 구조에 어떻게 적용할지 고릅니다.
쉬운 답장
이 트렌드를 Phoenix 수업용 자동화 서비스 구조로 바꿔줘. 각 봇에게 맡길 작업도 같이 정리해줘.
오전 8시 학습 강화 메시지
유저 대응
메시지
Genesis가 더 잘 지휘하도록 좋은 전체 지시문, 실패한 업무 분장, 수정 피드백, 최종 승인 기준을 샘플로 남기라고 안내합니다.
유저 역할
잘된 지시문과 부족했던 지시문을 비교해서 “다음부터 반드시 포함할 항목”을 체크리스트로 만들게 합니다.
강화 포인트
학습 재료는 1. 좋은 전체 지시문 2. 잘못 나눈 업무 분장 3. 수정 피드백 4. 승인 기준 5. 다음 지시문 템플릿으로 남기면 효과가 큽니다.
업데이트 파일
AGENTS.md, HEARTBEAT.md, skills/SKILL.md, USER.md
복사용 명령문
명령문 복사
Genesis Bot, 이번 작업에서 나온 좋은 전체 지시문/나쁜 업무 분장/수정 피드백을 학습 샘플로 정리해줘.
업데이트 후보 파일은 AGENTS.md, HEARTBEAT.md, skills/SKILL.md, USER.md로 명시해줘.
각 파일별로 추가할 문구, 수정할 체크리스트, 다음 작업에서 사용할 예시 프롬프트를 구분해서 제안해줘.
민감값은 절대 출력하지 말고, 실제 파일은 직접 수정하지 말고 변경안만 보여줘.
쉬운 답장
이번 작업 지시문을 학습 샘플로 정리해줘. 좋은 점, 부족한 점, 다음 지시문 체크리스트, 금지사항까지 남겨줘.
실제 작업 제안 메시지
유저 대응
메시지
Genesis가 오늘 바로 맡을 수 있는 지휘·설계·분장 작업 하나를 고릅니다.
유저 역할
결과물 형식을 좁혀서 실행시킵니다. 범위가 크면 표나 단계별 문서로 제한합니다.
쉬운 답장
진행. 결과물은 봇별 작업표, 진행 순서, 확인 체크리스트로 정리해줘.
오후 5시 스킬 강화 메시지
유저 대응
메시지
멀티봇 지휘, 서비스 구조화, 자동화 요구사항 작성 같은 Genesis의 스킬 강화 아이디어를 요청합니다.
유저 역할
승인 전에는 어떤 지시문 템플릿, 업무 분장 기준, 자동화 요구사항 체크리스트가 추가되는지 확인합니다.
강화 포인트
강화 제안은 바로 반영하지 말고 1. 강화 목적 2. 바뀔 스킬 항목 3. 예시 문구 4. 되돌릴 방법 5. updater 반영 범위를 확인한 뒤 승인합니다.
업데이트 파일
AGENTS.md, HEARTBEAT.md, skills/SKILL.md, IDENTITY.md
복사용 명령문
명령문 복사
Genesis Bot, 멀티봇 지휘와 업무 분장 능력을 강화하기 위한 스킬업 변경안을 제안해줘.
업데이트 대상 파일은 AGENTS.md, HEARTBEAT.md, skills/SKILL.md, IDENTITY.md로 명시해줘.
각 파일에 어떤 항목을 추가/수정할지, 적용 전후 예시, 위험한 변경 여부, 되돌리는 방법을 표로 작성해줘.
마스터 승인 전에는 파일을 직접 수정하지 말고 updater 반영용 변경안만 작성해줘.
쉬운 답장
승인. 적용 전에 어떤 파일과 문구가 바뀌는지, 지시문 템플릿 예시와 체크리스트를 먼저 보여줘.
운영 팁: Genesis에게는 “전체 그림”을 먼저 주세요. 결과물 이름, 참여할 봇, 마감 순서, 금지사항을 말하면 다른 봇을 훨씬 정확히 움직입니다.
