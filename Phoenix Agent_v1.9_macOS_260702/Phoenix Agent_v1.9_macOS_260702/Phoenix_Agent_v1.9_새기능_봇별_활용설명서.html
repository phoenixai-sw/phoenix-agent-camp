Phoenix Agent v1.9 새 기능 봇별 활용 설명서

대상: Phoenix Agent v1.9를 설치하거나 업데이트한 유저 / 목적: Telegram 봇이 보내는 자동 제안 메시지를 실제 업무로 연결하기

v1.9의 핵심은 “자동 제안 기능은 유지하면서, 모델 인증을 여러 방식 중에서 명확히 선택할 수 있게 만든 구조”입니다.

이 문서는 준비 완료 알림, 30분 미시작 제안, 3시간 idle 요약, 오전 7시 최신 트렌드 제안, 오전 8시 스킬 학습 안내, 실제 작업 제안, 오후 5시 스킬 강화 요청, 그리고 v1.9 인증 선택 방식을 봇별로 정리합니다.

중요 보안 원칙

Telegram token, API Key, OAuth credential 값은 채팅에 붙이지 않습니다. 민감값은 설치/업데이트 가이드에서 안내한 파일 방식으로만 다룹니다.

1. v1.9 핵심: 인증 선택과 명확한 fallback

v1.9은 “어떤 모델 인증으로 움직이는지”를 숨기지 않습니다

v1.9의 가장 큰 특징은 Codex CLI ChatGPT 인증을 기본으로 쓰되, 상황에 따라 ChatGPT 브라우저 인증, Gemini API, local/Open Source LLM 후보까지 명확히 구분해 운영할 수 있다는 점입니다.

중요한 기준은 “조용히 다른 모델로 넘어가지 않는 것”입니다. 유저가 지금 GPT-5.5로 답변을 받는지, Gemini 2.5 Flash 후보를 쓰는지, local LLM 후보를 쓰는지 헷갈리지 않도록 인증 상태와 선택된 provider/model을 보고하게 합니다.

1순위

Codex CLI 인증

용도
기본 대화 인증입니다. Codex CLI에 로그인된 ChatGPT 구독 계정 인증을 기준으로 OpenClaw 봇이 모델을 사용합니다.
기준
openai/gpt-5.5가 정상이고 PM2, Gateway, Telegram이 살아 있으면 이 방식이 우선입니다.
유저 대응
Codex 앱과 Antigravity IDE에서는 내부 터미널에서 로그인 상태를 복구한 뒤 updater 점검을 실행합니다. Claude 앱에서는 Code 항목에서 Claude Code에게 로그인 복구와 updater 점검을 지시합니다.
2순위

ChatGPT 브라우저 인증

용도
Codex CLI 인증이 없거나 만료되어 브라우저 승인이 필요한 경우 사용합니다.
기준
브라우저가 열리면 ChatGPT 구독 계정으로 승인하고, 승인 후 auth 상태와 만료 시각만 확인합니다.
주의
OAuth credential 값은 절대 화면에 출력하지 않습니다. 성공/실패와 유효 여부만 보고합니다.
fallback 후보

Gemini API 인증

용도
GPT 인증이 막히거나 별도 모델 운영이 필요한 경우를 위한 명시적 fallback 후보입니다.
기본 모델
기본 모델은 gemini-2.5-flash입니다. 필요한 값은 “2. 인증키_에이전트 모델 인증 키 모음” 폴더의 gemini_api_key.txt, gemini_model.txt 파일로 준비합니다.
운영 원칙
GPT에서 Gemini로 조용히 넘어가지 않습니다. Gemini를 쓰는 경우 현재 provider/model을 보고하게 합니다.
fallback 후보

local/Open Source LLM 인증

용도
기관망, 폐쇄망, 내부 서버 환경에서 외부 AI 연결이 어렵거나 local LLM을 써야 할 때를 위한 후보입니다.
입력 파일
local_llm_base_url.txt, local_llm_model.txt, local_llm_api_key.txt 파일로 endpoint, 모델명, 필요한 인증값을 준비합니다.
운영 원칙
local LLM 사용 시에도 “현재 local 모델로 동작 중”임을 명확히 표시해야 합니다.

2. v1.9 자동 메시지를 이해하는 법

메시지를 받으면 이렇게 판단하세요

v1.9의 자동 메시지는 단순 알림이 아니라, 봇이 지금 할 수 있는 다음 일을 먼저 제안하는 운영 안내입니다.

메시지를 받으면 먼저 “왜 왔는지”를 확인하고, 그 다음 “진행 / 수정 / 보류 / 샘플 제공 / 승인” 중 하나로 답하면 됩니다. 봇마다 성격과 스킬이 다르기 때문에 같은 자동 메시지라도 실제 활용 방식은 조금씩 달라집니다.

로컬 노트북 활성 조건

Phoenix Agent는 로컬 노트북에서 움직이는 에이전트입니다. 노트북이 켜져 있고 잠자기/절전 상태가 아니며, PM2와 phoenix_proactive_nudge runner, 인터넷 연결이 살아 있을 때 Telegram 메시지를 보낼 수 있습니다.

노트북이 잠들어 있거나 꺼져 있으면 그 시간에는 메시지가 발송되지 않습니다. 다시 깨어난 뒤에는 runner가 현재 상태를 확인하고, 조건에 맞는 복구/준비 완료/제안 메시지를 이어서 처리합니다.

정기 메시지 시간 기준

오전 7시 트렌드 제안, 오전 8시 스킬 학습 안내, 오후 5시 스킬 강화 요청은 정해진 시간대에 runner가 깨어 있을 때 발송됩니다.

해당 시간대 전체를 노트북이 잠든 상태로 지나가면 그 정기 메시지는 자동으로 몰아서 보내지 않습니다. 재시동 준비 알림은 재시동/복구 상황 기준이고, 3시간 무응답 요약은 실제 유저 입력 이후의 무응답 시간을 기준으로 따로 판단합니다.

재시동 직후준비 완료 알림을 받으면 /new 후 상태 확인 메시지를 보냅니다.
30분 미시작봇이 첫 작업을 제안하면 마음에 드는 작업명 또는 “진행”이라고 답합니다.
3시간 무응답요약을 읽고 이어서 할 작업, 보류할 작업, 새로 시작할 작업을 골라 답합니다.
오전 7시최신 트렌드 제안이 오면 참고 링크를 확인하고 업무화할 방향을 골라줍니다.
오전 8시좋은 샘플과 피드백을 남겨 봇의 다음 업데이트 재료로 만듭니다.
오후 5시스킬 강화 요청을 검토하고 승인/보류/수정 요청 중 하나로 답합니다.

3. v1.9 자동 메시지를 이해하는 법 (봇 별로 구분)

봇마다 같은 자동 메시지도 의미와 대응법이 다릅니다

v1.9 실행기는 봇별 역할, 작업 메뉴, 트렌드 검색어, 스킬 강화 요청, 학습 샘플, 인증 선택 상태를 다르게 넣어서 Telegram 메시지를 보냅니다.

특히 오전 8시 학습 강화 메시지와 오후 5시 스킬 강화 메시지는 봇 품질을 올리는 핵심입니다. 이 두 메시지는 단순 답장이 아니라, 어떤 파일을 업데이트 후보로 삼을지까지 명시한 명령문으로 대응해야 합니다.

1단계봇 이름을 확인합니다. 봇마다 맡길 일이 다릅니다.
2단계학습 강화와 스킬 강화는 업데이트 후보 파일을 반드시 확인합니다.
3단계복사용 명령문을 봇에게 보내고, 봇이 제안한 변경안은 마스터 승인 후 updater로 반영합니다.

Genesis Bot

비서실장 봇

전체 봇을 지휘하고 작업 구조를 잡는 총괄형 봇입니다. 메시지를 받으면 “무엇을 누구에게 맡길지”를 결정하는 관점으로 대응하면 좋습니다.

봇 성격전체 봇을 관리하고, 작업 지시문·자동화 흐름·서비스 구조를 정리하는 지휘형 봇입니다.
메시지에서 보는 핵심전체 작업 순서, 봇별 업무 분장, 자동화 설계, 서비스/플랫폼 구조가 핵심입니다.
유저의 역할목표와 우선순위를 알려주고, Genesis가 다른 봇에게 나눠 줄 지시문을 검토하는 승인자 역할을 합니다.
읽는 순서: 먼저 메시지 종류를 확인하고, 그 다음 유저 역할을 읽은 뒤, 쉬운 답장 예시를 그대로 보내거나 내 상황에 맞게 한 줄만 바꾸면 됩니다. 학습 강화와 스킬 강화는 반드시 업데이트 파일과 복사용 명령문까지 확인합니다.

유저 역할
오늘의 전체 목표를 말하고, 어느 봇부터 움직일지 결정합니다.
쉬운 답장

메시지

유저 역할

강화 포인트

5. 봇 실력을 빠르게 올리는 방법

좋은 샘플을 보여주기원하는 결과물의 예시, 문체, 디자인, 구성 순서를 보여주면 봇이 훨씬 빨리 맞춥니다.
나쁜 예시도 남기기마음에 들지 않는 결과와 이유를 남기면 다음 작업에서 같은 실수를 줄일 수 있습니다.
체크리스트로 만들기완성도 기준을 체크리스트로 남기면 다음 업데이트에서 스킬 기준으로 반영하기 쉽습니다.
승인된 기준만 반영하기봇은 제안자입니다. 실제 스킬 파일 반영은 마스터 승인 후 updater로 처리합니다.
샘플 학습 요청 문장
이번 결과에서 좋은 점, 부족한 점, 다음 작업에 꼭 반영할 체크리스트를 정리해줘.
좋은 샘플은 출력 예시, 문체 기준, 구성 순서, 금지사항, 완성도 체크리스트로 나눠서 정리해줘.
나중에 updater로 반영할 수 있게 스킬 개선 제안 형식으로 써줘.

6. 메시지가 안 오거나 답변이 없을 때

Telegram에서 먼저 말 걸기봇에게 `/start` 또는 `/new`를 한 번 보낸 적이 있어야 봇이 먼저 메시지를 보낼 수 있습니다.
준비 완료 기준 확인PM2 online, Gateway health OK, Telegram configured/enabled, 선택된 모델 인증 유효 상태가 필요합니다. 기본은 openai/gpt-5.5이며, Gemini/local LLM은 명시적으로 선택하거나 fallback 후보로 구분합니다.
인증 만료 확인모델 로그인 실패가 보이면 먼저 Codex CLI ChatGPT 로그인을 복구하고, 필요하면 ChatGPT 브라우저 인증을 진행합니다. Gemini 또는 local LLM을 쓰는 경우에는 현재 provider/model이 명확히 표시되어야 합니다.
스팸처럼 보이면하루 최대 10회 제한이 있으니, 같은 날 이미 많이 받은 경우 다음 날 다시 확인합니다. 단, 07:00/08:00/17:00 핵심 예약 메시지는 그날 아직 안 보낸 경우 늦게 켜져도 1회 보정 발송됩니다.
v1.9의 자동 메시지는 “사용자를 방해하려는 알림”이 아니라 “지금 바로 맡길 수 있는 다음 작업을 제안하는 운영 보조 기능”입니다. 여기에 인증 선택 상태까지 명확히 표시해, 유저가 어떤 모델 기준으로 봇을 쓰는지 알 수 있게 합니다. 마음에 들면 “진행”, 다르게 하고 싶으면 조건을 붙여 답하면 됩니다.

7. Phoenix Agent v1.9의 특징은 무엇인가

v1.9 = v1.7 기본 기능 기반 + PCS + PTS

Phoenix Agent v1.9은 완전히 새로 갈아엎는 버전이 아닙니다. 현재 안정 운영 중인 기본 기능을 그대로 유지하고, 여기에 Codex 스킬업 기능 2개(PCS·PTS)만 더한 제품화 업그레이드입니다.

PCS = Phoenix Copy SkillMac에서 작업을 한 번 보여주면 그 흐름을 재사용 가능한 스킬로 만드는 기능입니다. (공식 Codex 기능: Record & Replay)
PTS = Phoenix Talk Skill좋은 대화·보고서·결과물을 정리해 재사용 가능한 스킬로 만드는 기능입니다. (공식 Codex 기능: Skill Creator / $skill-creator)

그대로 유지되는 기본 기능

Genesis / Power / Design / Video / Writer 5개 전문 봇 OpenClaw 기반 Telegram 연결, PM2 실행 구조 proactive runner와 준비 완료·트렌드·스킬 학습·스킬 강화 자동 메시지 선택형 멀티 인증(ChatGPT/Codex · Gemini · Local/Open Source LLM) outputs/logs 보존, 민감값 미출력 원칙 Windows/macOS 배포와 cleaner · installer · updater 체계

v1.9에서 새로 추가

PCS · PTS 두 가지 Codex 스킬업 기능 두 기능 모두 "봇이 후보를 제안 → 마스터 승인 후 장착" 구조로 동작 자세한 사용법은 바로 다음 8. PCS / PTS 스킬업에서 설명합니다.
제품 표기 원칙: 내부 개발 기준은 v1.7_260626 안정판을 기반으로 하지만, 클리너·인스톨러·업데이터·가이드·실행 배너·완료 메시지·문서 제목·배포 폴더명·zip 파일명 등 사용자에게 보이는 모든 곳은 Phoenix Agent v1.9로만 표기합니다. (source_version=v1.7_260626 같은 표현은 개발자 전용 로그·migration metadata에서만 허용됩니다.)

8. PCS / PTS 스킬업

봇의 실력을 "재사용 가능한 스킬"로 굳히는 두 가지 방법

PCS는 작업 과정을 녹화해서, PTS는 좋은 대화·결과물을 정리해서 각각 재사용 가능한 스킬 후보로 만듭니다. 봇은 후보를 제안만 하고, 실제 장착은 마스터 승인 후에 이뤄집니다.

12. Windows 화면녹화 정책

Windows 화면녹화 영상은 PCS 공식 녹화 대체물이 아닙니다. 즉, Windows 화면녹화 파일을 올려 Record & Replay와 동일한 PCS 스킬을 자동 생성할 수는 없습니다. 대신 PTS 재료로 사용합니다.
1. 화면녹화Windows에서 작업 과정을 녹화합니다.
2. 절차 정리작업 절차를 텍스트로 정리합니다.
3. PTS 프롬프트봇에게 PTS 프롬프트 작성을 요청합니다.
4. 스킬 생성Codex $skill-creator 실행 → SKILL.md 후보 생성.
5. 저장skill_candidates에 저장합니다.
6. 승인·장착마스터 승인 후 .agents/skills에 장착합니다.
