설치용 인증키 폴더 안내

인스톨러는 유저가 준비한 인증키 파일을 읽어 새 봇을 설치합니다. 이 파일들은 1. 인증키_API 키 모음과 2. 인증키_에이전트 모델 인증 키 모음에 준비한 뒤 안내에 따라 installer 폴더로 이동하거나 참조합니다.

이 인증키 모음은 신규 설치 입력 자료이며, 클리너가 삭제하는 설치된 봇 런타임 credential과 구분됩니다.

이 문서에서 권장하는 진행 방식: 실행은 반드시 Antigravity IDE 내부 터미널에서 Codex CLI 또는 Claude Code가 연결된 상태로 진행합니다. 아래 프롬프트는 IDE 내부 터미널의 에이전트 세션에 붙여 넣는 작업 지시문입니다.

민감한 정보는 파일로 받습니다. Telegram token, chat id, pairing code, API key를 채팅창이나 터미널 입력으로 받지 않습니다. ChatGPT 구독 계정 인증만 브라우저 창에서 진행합니다.

1. 설치 전 준비 파일

빈 입력 템플릿은 패키지 루트의 1. 인증키_API 키 모음 폴더에 있습니다. 유저는 필요한 파일에 값을 한 줄로 입력한 뒤, 실제 설치 실행 전에 해당 파일을 installer 폴더로 복사/이동합니다. installer 폴더에는 처음부터 빈 민감값 파일을 넣어두지 않습니다.

Windows 탐색기에서 확장자가 숨겨져 있으면 telegram_access_token처럼 보일 수 있지만 실제 파일명은 telegram_access_token.txt입니다.

파일명필수 여부용도
telegram_access_token.txt필수BotFather에서 받은 해당 봇의 Telegram Bot Token 한 줄
telegram_chat_id.txt필수준비 완료 알림을 받을 Telegram chat id 한 줄
openai_api_key_image.txt선택Design/Writer 이미지 생성 등 기능용 OpenAI API Key. 대화 인증용이 아닙니다.
falai_api_key_video.txt선택Video Bot의 fal.ai 영상 생성 기능용 API Key
telegram_pairing_code.txt설치 후 필요할 때Telegram에서 pairing code가 나온 뒤, 그 코드 한 줄만 넣어 승인합니다.
gemini_api_key.txt선택Gemini 선택 인증 설치 또는 명시적 fallback용 API key. 기본 모델은 gemini-2.5-flash입니다. Gemini 사용 시 반드시 Gemini라고 표시합니다.
gemini_model.txt선택Gemini 모델명을 바꿀 때만 사용합니다. 비워두면 gemini-2.5-flash를 사용합니다.
local_llm_base_url.txt선택OpenAI-compatible local/Open Source LLM 서버 주소. 예: 내부 Ollama/LM Studio/vLLM adapter 주소
local_llm_model.txt선택local/Open Source LLM 모델명. local_llm_base_url.txt와 함께 있어야 후보로 등록됩니다.
local_llm_api_key.txt선택local LLM endpoint가 API key를 요구할 때만 사용합니다. 값은 출력하지 않습니다.

파일명이 openai_api_key_image, falai_api_key_video, telegram_access_token, telegram_chat_id, telegram_pairing_code, gemini_api_key, gemini_model, local_llm_base_url, local_llm_model, local_llm_api_key처럼 보이면 Windows/macOS의 확장자 숨김 상태일 수 있습니다. 속성 또는 표시 옵션에서 실제 .txt 여부를 확인하세요. Telegram 필수 파일과 이미지/영상 기능키는 작성이 끝난 파일만 installer 폴더로 옮깁니다. Gemini/local LLM 모델 인증 파일 5개는 패키지 루트의 2. 인증키_에이전트 모델 인증 키 모음 폴더에 둡니다.

2. 설치 프로그램이 자동으로 처리하는 것

  • 기존 봇 작업 폴더나 PM2를 정리하기 전에, 유저가 값을 입력해 installer 폴더로 옮긴 telegram_access_token.txt와 telegram_chat_id.txt 존재/형식을 먼저 검사합니다.
  • 필수 파일이 없으면 설치를 시작하지 않고 어떤 파일이 필요한지 알려줍니다.
  • OpenAI OAuth(Codex import) / openai/gpt-5.5을 1순위로 확인하고, 이후 봇은 같은 Codex CLI 인증 기준을 재사용합니다. Codex CLI 로그인이 없거나 만료된 경우에만 codex login 브라우저 인증을 진행합니다.
  • 모델 인증 파일이 2. 인증키_에이전트 모델 인증 키 모음 폴더에 있으면 gemini_api_key.txt, gemini_model.txt, local_llm_base_url.txt, local_llm_model.txt, local_llm_api_key.txt를 읽어 봇별 .env와 phoenix_model_fallback.json에 기록합니다. 단, Gemini/local LLM은 GPT-5.5가 아니므로 메시지에 반드시 명시합니다. 루트 인증키 폴더는 원본 템플릿 보관 위치이므로 installer가 삭제하지 않고, installer 폴더에 복사된 민감 파일만 삭제 여부를 묻습니다.
  • 봇 정체성 파일 IDENTITY.md, AGENTS.md, SOUL.md, USER.md, HEARTBEAT.md, skills/SKILL.md를 생성하고, 봇별 역할 문구와 선택 인증 문구가 실제로 들어갔는지 내용까지 검증합니다.
  • v1.7 proactive 정책으로 준비 완료 후 30분 제안, 3시간 idle 요약, 오전 7시 최신 트렌드 제안, 오전 8시 스킬 학습 안내, 하루 1회 스킬 작업 제안, 오후 5시 트렌드 기반 스킬 강화 요청을 설정합니다.
  • 준비 완료 메시지, 30분 미시작 제안, 3시간 idle 요약, 오전 7시 최신 트렌드 제안, 오전 8시 스킬 학습 안내, 오후 5시 트렌드 기반 스킬 강화 요청 실행기를 등록합니다.
  • 재시동 이후에도 작동하도록 macOS LaunchAgent ai.openclaw.phoenix.pm2.plist를 등록해 pm2 resurrect와 준비 완료 알림을 자동 실행합니다.
  • 봇별 메시지는 10초 간격으로 순차 발송되도록 설정합니다.

2-1. 미인증/부분 설치 방지 및 복구 기준

인스톨러는 설치 전 선검사 후 진행합니다. 유저가 값을 입력해 installer 폴더로 옮긴 telegram_access_token.txt와 telegram_chat_id.txt가 없거나 비어 있으면 기존 봇 폴더나 PM2를 건드리기 전에 멈춥니다. 그래서 잘못된 파일 준비 때문에 기존 설치가 반쯤 지워지는 일을 막습니다.
  • Codex CLI First 인증: 인스톨러가 먼저 codex login status를 확인합니다. 유효하면 현재 Codex CLI ChatGPT 로그인을 OpenAI OAuth(Codex import)로 봇 프로필에 연결하고, 없거나 만료되면 codex login 브라우저 인증을 진행한 뒤 phoenix_v19_auth_order_repair.cjs로 openai/gpt-5.5 인증 순서를 보정합니다. credential 값은 출력하지 않습니다.
  • provider plugin 누락: 설치 중 clawhub:@openclaw/codex 기준을 확인하고, 이후 모델 인증이 openai/gpt-5.5로 고정되었는지 보고합니다.
  • PM2에 아직 없는 봇: 첫 설치에서는 PM2 프로세스가 없는 것이 정상입니다. 없는 프로세스 삭제 실패 때문에 설치가 중단되지 않아야 합니다.
  • 준비 완료 메시지 실패: PM2, Gateway, Codex ChatGPT login이 정상이고 Telegram 발송만 실패한 경우에는 설치 실패와 분리해서 보고합니다.
  • 설치 후에도 답변이 없을 때: 같은 코딩 에이전트 내부 터미널에서 OpenAI/Codex 모드이면 codex login으로 Codex CLI ChatGPT 로그인을 복구한 뒤 updater를 실행합니다. Gemini 선택 인증 모드이면 gemini_api_key.txt, gemini_model.txt, provider=google, model=google/gemini-2.5-flash 계열 설정과 openclaw config validate --json 결과를 확인한 뒤 updater를 실행합니다.

3. 설치 전 모델 인증 방식 선택

먼저 모델 인증 방식을 선택한 뒤, 아래의 봇별 설치 프롬프트를 실행합니다.

Codex CLI, Claude Code, Antigravity IDE는 설치 명령을 실행하는 도구입니다. Gemini API 또는 local LLM은 봇이 답변할 때 사용할 모델 인증 후보입니다. 이 둘을 섞어서 설명하면 유저가 헷갈리므로 반드시 분리해서 안내합니다.

선택언제 사용하나준비 파일보고 기준
기본 권장ChatGPT 구독 계정과 Codex CLI 인증을 기본으로 쓸 때Telegram 필수 파일openai/gpt-5.5 인증 유효 여부와 만료 시각만 보고합니다.
Gemini 선택 인증OpenAI/Codex 대신 Gemini API를 봇 답변 모델 인증으로 선택할 때gemini_api_key.txt, gemini_model.txtprovider/model이 Gemini인지 명확히 보고합니다. 기본 모델은 gemini-2.5-flash입니다.
local LLM 후보기관망, 폐쇄망, 내부 서버 모델을 쓰고 싶을 때local_llm_base_url.txt, local_llm_model.txt, local_llm_api_key.txt현재 local model인지, 아직 후보만 설정된 상태인지 구분해서 보고합니다.

Gemini API 인증을 선택해서 설치하고 싶을 때

  1. 패키지 루트의 2. 인증키_에이전트 모델 인증 키 모음 폴더를 엽니다.
  2. gemini_api_key.txt에 Gemini API Key를 한 줄로 입력합니다. 값은 채팅창이나 보고서에 출력하지 않습니다.
  3. gemini_model.txt에는 모델명을 입력합니다. 비워두면 gemini-2.5-flash를 기본 후보로 사용합니다.
  4. 아래 Gemini 선택 인증 프롬프트는 인증 방식만 고정하는 사전 지시문입니다. 이 프롬프트만으로 설치를 시작하지 말고, 반드시 바로 아래의 봇별 설치 프롬프트 또는 명시적 설치 명령을 이어서 실행합니다.
  5. macOS에서 Gemini 선택 인증 설치를 실제로 실행할 때는 봇별 명령에 --auth gemini를 붙입니다. 예: bash ./install_genesis_bot.command --auth gemini
  6. 전체 메뉴 installer를 실행할 때도 --auth gemini 옵션을 붙일 수 있습니다. 예: bash ./install_phoenix_agent.command --auth gemini
Phoenix Agent v1.9 설치 전 모델 인증 방식을 Gemini 선택 인증으로 설정합니다.

중요:
- Codex CLI, Claude Code, Antigravity IDE는 설치 명령을 실행하는 도구입니다.
- 봇이 답변할 때 사용할 모델 인증을 Gemini API로 선택해 주세요.
- 이 프롬프트만으로 install_* 명령을 실행하지 마세요. 실제 설치는 봇별 설치 프롬프트가 들어오거나 명시적 설치 명령이 있을 때만 시작하세요.
- ChatGPT/Codex 인증이 있어도 Gemini 설치 요청을 GPT-5.5로 숨기지 마세요.
- 모델 인증 키 폴더는 패키지 루트의 2. 인증키_에이전트 모델 인증 키 모음 입니다.

- installer/telegram_pairing_code.txt가 있으면 최종 완료 전에 approve helper로 승인하고 Pairing code approved 상태를 보고하세요.

- 준비 완료 보고에는 PM2 online, Gateway health OK, Telegram configured/enabled, 선택한 모델 인증 상태, provider/model을 포함하세요.

이 기준을 유지한 상태에서 아래 봇별 설치 프롬프트를 이어서 실행해 주세요.

주의: Gemini API Key가 있다고 해서 자동으로 GPT-5.5와 같은 방식으로 조용히 바뀌면 안 됩니다. v1.7 원칙은 “현재 어떤 provider/model로 동작하는지 명확히 표시”하는 것입니다.

5. 봇별 기능 및 특징

Phoenix Agent v1.9 봇 운영 요약

설치 후 생성되는 5개 봇이 어떤 일을 잘하고, v1.9 자동 메시지에서 무엇을 제안하는지 정리한 섹션입니다.

v1.9은 준비 완료 알림에서 끝나지 않고, 미시작 제안, 3시간 idle 요약, 최신 트렌드 제안, 스킬 학습 안내, 실제 작업 제안, 트렌드 기반 스킬 강화 요청까지 이어집니다.

봇은 스스로 파일을 바꾸지 않고 좋은 제안을 먼저 보냅니다. 실제 스킬 반영은 마스터 승인 후 updater로 처리하여 정체성과 동작이 꼬이지 않게 운영합니다.

준비 완료PM2, Gateway, Telegram, 선택 모델 인증 확인
30분 제안준비 후 시작하지 않으면 다음 작업 제안
3시간 요약무응답 시 최근 흐름과 다음 액션 정리
오전 7시봇별 최신 트렌드 검색과 작업 메뉴 제안
오전 8시좋은 샘플과 체크리스트 기반 스킬 학습 안내
오후 5시트렌드 기반 스킬 강화 요청
v1.9 자동 메시지 타입: ready_start_suggestion, idle_summary, trend_digest, skill_learning_guidance, skill_work_offer, skill_upgrade_request. 각 메시지는 봇별 역할에 맞춰 작성되며, 최신 정보가 필요한 제안은 검색 근거와 참고 링크를 함께 붙이는 기준입니다.

Phoenix Agent v1.9 PCS/PTS 스킬업

PCS: Phoenix Copy Skill

Codex Record & Replay로 실제 작업 과정을 기록하고 재현 가능한 스킬 후보로 정리합니다. 공식 기록 기준은 macOS 우선이며, Windows 사용자는 PTS를 쓰거나 검수된 macOS PCS 결과물을 가져옵니다.

PTS: Phoenix Talk Skill

Codex Skill Creator 방식으로 좋은 예시, 보고서, 페이지 구조, 영상 대본, 원고, 작업 메모를 재사용 가능한 스킬 후보로 만듭니다.

승인 원칙

봇은 스킬 후보를 제안할 수 있지만 active skill을 직접 바꾸지 않습니다. 마스터 승인 후 updater 또는 검수 절차를 통해 .agents/skills에 반영합니다.

업데이트 원칙: v1.6/v1.7/v1.8 기존 설치본은 updater로 v1.9까지 올립니다. v1.5 설치본은 cleaner 후 v1.9 installer 사용을 권장합니다.

v1.9 24시간 Agent 운영 가이드

노트북 덮개 닫기 운영은 Phoenix Agent 소프트웨어 기능이 아니라 OS/하드웨어 설정입니다. 로컬 봇은 MacBook이 켜져 있고, 잠자기 상태가 아니며, 인터넷과 PM2/OpenClaw gateway가 살아 있을 때만 계속 동작합니다.

메뉴항목설명
1. 운영 원칙켜짐 + 인터넷 + PM2 online전원이 꺼지거나 배터리가 방전되거나 잠자기 상태가 되면 로컬 봇은 멈춥니다.
2. macOS 설정시스템 설정 > 배터리 > 전원 어댑터 / 옵션전원 어댑터 연결 시 잠자기 방지 설정을 확인합니다. macOS 버전에 따라 메뉴 이름이 조금 다를 수 있습니다.
3. 닫힌 덮개 조건전원 어댑터, 외부 디스플레이/키보드/마우스 조건MacBook은 덮개를 닫으면 기본적으로 잠자기에 들어가려는 성향이 있으므로, 장시간 운영 조건을 별도로 확인해야 합니다.
4. 선택형 도우미configure_laptop_awake_mode.commandinstaller와 updater 폴더에 각각 들어 있습니다. 현재 설정 확인, 전원 어댑터 기준 잠자기 방지 적용, 임시 keep-awake 실행 중 하나를 메뉴로 선택합니다.

방법 1. installer 폴더에서 실행

새로 설치하는 유저가 installer 폴더 안에서 실행합니다. 설치 전이나 설치 후에 현재 전원 설정을 확인하고, 필요할 때만 옵션을 적용합니다.

chmod +x ./configure_laptop_awake_mode.command 2>/dev/null || true
./configure_laptop_awake_mode.command

방법 2. updater 폴더에서 실행

기존 v1.6/v1.7/v1.8 사용자가 v1.9 updater를 실행할 때 같은 updater 폴더 안에서 실행합니다. 업데이트만 하는 유저는 이 방법을 쓰면 됩니다.

chmod +x ./configure_laptop_awake_mode.command 2>/dev/null || true
./configure_laptop_awake_mode.command

방법 3. Genesis Bot에게 지시해서 진행

명령어가 부담스러운 유저는 Genesis Bot에게 아래 지시문을 보내면 됩니다. Genesis Bot은 먼저 확인만 하고, OS 설정을 바꾸기 전에는 무엇을 바꿀지 보고하고 승인받아야 합니다.

Genesis Bot, Phoenix Agent v1.9 24시간 Agent 운영 설정을 도와줘.

목표:
- MacBook 덮개를 닫아도 봇이 계속 돌 수 있는지 확인
- 전원 어댑터/잠자기/pmset 상태 확인
- installer 또는 updater 폴더 안의 configure_laptop_awake_mode.command 파일을 찾아 먼저 현재 설정만 확인
- 토큰/API Key/OAuth 값은 절대 출력하지 말 것
- sudo나 OS 설정 변경이 필요하면 먼저 무엇을 바꿀지 보고하고 내 승인을 받을 것

먼저 현재 폴더 위치와 도우미 파일 존재 여부를 확인하고, 실행 가능한 방법을 짧게 보고해줘.
중요: 이 기능은 봇 자체 기능이 아니라 macOS 전원 설정과 MacBook 하드웨어 상태가 함께 맞아야 동작합니다. 전원 OFF, 배터리 방전, 인터넷 끊김 상태에서는 로컬 봇이 계속 활동할 수 없습니다.
