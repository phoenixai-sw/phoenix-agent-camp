Phoenix Agent v2.0 공식 운영 문서

PCS/PTS 스킬업 운영가이드

이 문서는 Phoenix Agent 봇과 유저가 v2.0의 스킬업 방식을 같은 기준으로 이해하도록 만든 안내서입니다. 봇은 스킬 후보를 정리하고, 마스터는 승인하며, Codex는 승인된 내용을 실제 파일로 반영합니다.

1. 이 문서를 쓰는 이유

유저

무엇을 보여주고 말해야 하는지 알기

좋은 샘플, 반복 업무, 화면 작업 순서, 결과물 기준을 어떻게 봇에게 전달해야 하는지 안내합니다.

봇

스킬 후보를 체계적으로 만들기

봇은 바로 스킬 파일을 고치지 않고, 마스터가 검토할 수 있는 후보 문서와 적용 지시문을 만듭니다.

Codex

승인된 후보만 실제 파일에 반영하기

Codex는 승인된 후보를 기준으로 skills, examples, checklist 파일을 만들고 검증합니다.

핵심 원칙: 봇은 제안자, 마스터는 승인자, Codex는 반영 도구입니다. 이 구분이 있어야 봇이 마음대로 정체성이나 스킬 파일을 바꾸는 사고를 막을 수 있습니다.

2. PCS와 PTS 한눈에 보기

구분 의미 언제 쓰나 대표 예시
PCS - Phoenix Copy Skill 유저가 실제 화면 작업이나 반복 업무를 보여주면, Codex가 관찰해서 스킬 후보를 정리하는 방식입니다. 클릭 순서, 사이트 탐색, 입력 절차, 반복 UI 작업처럼 말보다 보여주는 것이 빠를 때 씁니다. 경쟁사 사이트 조사, 보고서 양식 채우기, 디자인 레퍼런스 분류, 영상 업로드 체크리스트
PTS - Phoenix Talk Skill 유저가 좋은 샘플, 기준, 설명, 프롬프트를 말로 알려주면, 봇과 Codex가 재사용 가능한 스킬 후보로 정리하는 방식입니다. 보고서 형식, 문체, 기획 구조, 대본 구성처럼 설명과 예시로 기준을 만들 수 있을 때 씁니다. 시장분석 보고서, 상세페이지 구성, 숏폼 대본, 출판 원고 문체, 전체 봇 지시문 구조

macOS에서는 Codex의 Record & Replay 또는 Computer Use를 활용한 PCS 실습이 가장 자연스럽습니다. Windows에서는 PTS를 기본으로 쓰고, PCS가 필요한 경우 캡처 자료나 정리된 절차를 Codex에 전달해 후보안을 만들 수 있습니다.

3. 역할 분리

Master

마스터 / 유저

  • 스킬업 대상 업무를 선택합니다.
  • 좋은 샘플과 금지사항을 제공합니다.
  • 스킬 후보를 검토하고 승인합니다.
  • 민감정보가 들어가지 않았는지 최종 확인합니다.
Bot

Phoenix Bot

  • PCS 또는 PTS 중 적합한 방식을 제안합니다.
  • 부족한 정보를 질문합니다.
  • 스킬 후보 문서와 적용 지시문 초안을 정리합니다.
  • 직접 활성 스킬 파일을 수정하지 않습니다.
Codex

Codex

  • 승인된 후보를 파일 구조에 맞게 반영합니다.
  • 가이드, 스킬, 예시, 체크리스트 파일을 검증합니다.
  • 실행 파일과 패키지, 압축파일 반영 여부를 확인합니다.
  • 민감값은 출력하지 않습니다.

4. PCS 운영 방법

PCS가 잘 맞는 상황

  • 화면을 보면서 반복해서 처리하는 일이 있다.
  • 클릭 순서, 입력 위치, 확인 기준이 중요하다.
  • 말로 설명하면 길지만 직접 보여주면 빠르다.
  • Codex가 관찰한 절차를 나중에 체크리스트나 스킬로 재사용하고 싶다.

PCS 결과물에 반드시 들어갈 것

  • 스킬 이름과 대상 봇
  • 사용자가 보여준 업무 흐름
  • Codex가 관찰해야 할 포인트
  • 입력 자료와 출력 형식
  • 성공 기준, 실패 예외, 민감정보 주의사항
  • 활성 스킬 반영 체크리스트
PCS 상담 프롬프트 
PCS - Phoenix Copy Skill 설명:
PCS는 Phoenix Copy Skill의 약자입니다. 사용자가 실제 화면, 작업 순서, 클릭 흐름, 입력 위치, 확인 기준을 보여주면 그 과정을 관찰해서 봇이 다시 사용할 수 있는 실행형 스킬 후보로 정리하는 방식입니다. 화면을 보면서 배우는 방식이므로 웹사이트 이동, 폴더 정리, 디자인 도구 조작, 업로드/다운로드 절차, 반복 업무 자동화처럼 '순서와 화면 맥락'이 중요한 업무에 적합합니다. PCS의 목표는 단순한 설명이 아니라, 대상 봇이 다음부터 같은 업무를 더 정확하게 수행하도록 skills, examples, checklist에 반영할 수 있는 절차와 판단 기준을 만드는 것입니다.

PCS로 정리할 때 반드시 포함할 내용:
- 대상 봇과 스킬 이름
- 사용자가 보여준 실제 업무 흐름
- 화면에서 관찰해야 할 클릭, 입력, 확인 지점
- 필요한 입력 자료와 기대 출력 형식
- 성공 기준, 실패 예외, 민감정보 주의사항
- updater로 반영할 skills/examples/checklist 후보

Genesis Bot, 이 업무를 PCS 방식으로 스킬업할 수 있는지 상담해줘.

대상 봇:
스킬업하고 싶은 업무:
내가 화면으로 보여줄 수 있는 반복 과정:
최종 결과물 형식:
성공 기준:
주의할 민감정보:

먼저 PCS가 적합한지 판단하고, 부족한 질문을 한 뒤,
Codex가 기록하고 정리해야 할 PCS 스킬 후보안 형식으로 정리해줘.

5. PTS 운영 방법

PTS가 잘 맞는 상황

  • 좋은 샘플 문서, 보고서, 원고, 프롬프트가 있다.
  • 문체, 구성 순서, 금지사항, 품질 기준을 설명할 수 있다.
  • 화면 조작보다 결과물의 사고방식과 완성도 기준이 중요하다.
  • 봇이 다음 작업부터 같은 기준으로 답변하게 만들고 싶다.

PTS 결과물에 반드시 들어갈 것

  • 입력 자료와 사용자 의도
  • 작업 절차와 판단 기준
  • 출력 형식과 예시 프롬프트
  • 좋은 샘플의 특징
  • 나쁜 결과의 패턴과 금지사항
  • Codex가 반영할 파일 후보
PTS 상담 프롬프트 
PTS - Phoenix Talk Skill 설명:
PTS는 Phoenix Talk Skill의 약자입니다. 사용자가 좋은 샘플, 원고, 보고서, 대본, 프롬프트, 체크리스트, 문체 기준을 제공하면 그 안에 들어 있는 사고방식, 구성 순서, 품질 기준, 금지사항을 분석해서 봇이 재사용할 수 있는 스킬 후보로 정리하는 방식입니다. 화면 조작보다 결과물의 완성도와 판단 기준이 중요한 업무에 적합합니다. PTS의 목표는 봇이 한 번 본 샘플을 그대로 흉내 내는 것이 아니라, 좋은 결과가 나오는 원칙을 skills, examples, checklist로 분해해 다음 작업 품질을 높이는 것입니다.

PTS로 정리할 때 반드시 포함할 내용:
- 대상 봇과 스킬 이름
- 좋은 샘플 또는 참고 자료의 핵심 특징
- 원하는 결과물 형식과 문체 기준
- 구성 순서, 판단 기준, 품질 체크포인트
- 나쁜 결과 예시와 금지사항
- updater로 반영할 skills/examples/checklist 후보

Genesis Bot, 이 업무를 PTS 방식으로 스킬업하고 싶어.

대상 봇:
좋은 샘플 또는 참고 자료:
내가 원하는 결과물:
문체 또는 구성 기준:
반드시 지켜야 할 규칙:
나쁜 결과 예시 또는 피해야 할 방식:

이 내용을 바탕으로 봇이 재사용할 수 있는 스킬 후보안을 만들어줘.
후보안에는 skills, examples, checklist로 나누어 반영할 내용을 포함해줘.

6. PCS/PTS 선택 기준

업무 상황 추천 방식 이유
화면 클릭, 사이트 이동, 입력 순서가 핵심이다 PCS 실제 화면 흐름을 관찰해야 재사용 가능한 절차가 나옵니다.
좋은 보고서, 원고, 대본, 프롬프트 샘플이 있다 PTS 샘플의 구조와 품질 기준을 언어로 정리하는 것이 빠릅니다.
업무 기준을 말로 충분히 설명할 수 있다 PTS 봇이 질문을 통해 기준을 보강하고 스킬 후보를 만들 수 있습니다.
반복 업무를 직접 시연할 수 있다 PCS 또는 PTS 화면 절차가 중요하면 PCS, 결과물 기준이 중요하면 PTS를 선택합니다.

7. 봇별 스킬업 예시

Genesis Bot

전체 봇 지휘, 서비스 구조, 자동화 설계, 랜딩페이지 기획, 다중 봇 작업 지시문을 스킬업합니다.

예: “다섯 봇에게 나눠 맡기는 표준 지시문 구조를 PTS로 정리해줘.”

Power Bot

시장 조사, 트렌드 분석, 경쟁사 비교, 정부지원사업, 정책 요약, 보고서 구조를 스킬업합니다.

예: “좋은 시장분석 보고서 샘플을 기준으로 체크리스트를 만들어줘.”

Design Bot

상세페이지, PPT, 썸네일, 브랜드 비주얼, 이미지 콘셉트, 레퍼런스 분류 기준을 스킬업합니다.

예: “좋은 상세페이지 3개를 보고 디자인 판단 기준을 PTS로 정리해줘.”

Video Bot

숏폼 대본, 광고 영상 스토리보드, 첫 3초 훅, CTA, 자막, 영상 생성 프롬프트를 스킬업합니다.

예: “좋은 숏폼 영상 흐름을 보고 장면별 대본 규칙을 만들어줘.”

Writer Bot

원고 기획, 문체 유지, 교정 기준, 출판 이미지 목록, 카피라이팅, 목차 구성 방식을 스킬업합니다.

예: “좋은 원고 샘플을 기준으로 문체 규칙과 금지 표현을 정리해줘.”

10. 민감정보 금지 규칙

금지

후보안과 스킬 파일에 넣으면 안 되는 것

  • Telegram bot token, chat id
  • Gemini, OpenAI, fal.ai, local LLM API key
  • OAuth credential, pairing code
  • .env 원문
  • 비밀번호, 결제 정보, 주민번호, 고객 개인정보
허용

안전하게 남길 수 있는 것

  • 파일 존재 여부
  • 성공/실패 상태
  • 민감값을 제거한 예시 형식
  • 업무 절차와 품질 기준
  • 샘플 문서의 구조와 평가 기준
