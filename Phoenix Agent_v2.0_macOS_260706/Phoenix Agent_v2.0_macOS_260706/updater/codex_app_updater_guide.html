업데이트 시 인증키 보존 원칙

업데이터는 기존 봇의 연결 정보와 선택 인증 모드를 보존하면서 v2.0 기능을 갱신합니다. 설치 준비용 인증키 모음 폴더는 삭제하거나 초기화하지 않습니다.

Gemini/API/local LLM 선택 인증을 쓰는 경우에도, 가이드와 실행파일이 같은 인증 모드를 바라보도록 점검합니다.

실행 환경 구분

환경어디에서 진행하나해당 앱에서의 진행 방식
코덱스 앱
( Codex App )		 Codex 앱 내부 터미널

Codex CLI 영역

Codex CLI 확인: Codex 앱 내부 터미널에서 Codex CLI 설치 여부를 확인합니다.

codex --version

Codex CLI 설치: 없으면 아래 명령을 Codex 앱 내부 터미널에서 실행합니다.

npm install -g @openai/codex
여기부터는 Claude Code 영역입니다. Codex CLI와 구분해서 확인합니다.

Claude Code 영역

Claude Code 확인: Codex 앱 내부 터미널에서 Claude Code 설치 여부를 확인합니다.

claude --version

Claude Code 설치: 없으면 아래 명령을 Codex 앱 내부 터미널에서 실행합니다.

npm install -g @anthropic-ai/claude-code

실제 클리너/인스톨러/업데이터 명령도 Codex 앱 내부 터미널에서 실행합니다.

이 문서에서 권장하는 진행 방식: 실행은 반드시 Codex 앱 내부 터미널에서 codex CLI를 실행한 상태로 진행합니다. 아래 프롬프트는 Codex CLI 세션에 붙여 넣는 작업 지시문입니다.

업데이터는 재설치 도구가 아닙니다. 기존 봇을 지우지 않고, Codex CLI ChatGPT 로그인을 OpenAI provider OAuth로 import한 openai/gpt-5.5 인증 기준, Telegram token/chat id, outputs, logs를 보존한 채 v2.0_260706 실행기와 정체성 정책을 갱신합니다. 또한 v1.6/v1.7/v1.8/v1.9 설치본이 갖고 있지 못한 v2.0_260706 자동 메시지/인증 보강/릴리스 마커까지 기존 봇에 승급 적용합니다.

Gemini/local fallback 후보 설정

Codex CLI와 ChatGPT 브라우저 인증이 1순위와 2순위입니다. 필요한 경우에만 패키지 루트의 2. 인증키_에이전트 모델 인증 키 모음 폴더에 gemini_api_key.txt, gemini_model.txt, local_llm_base_url.txt, local_llm_model.txt, local_llm_api_key.txt를 준비합니다. 업데이터는 2. 인증키_에이전트 모델 인증 키 모음 폴더만 확인합니다. 업데이터는 값을 출력하지 않고 봇별 .env와 .openclaw/phoenix_model_fallback.json에 후보 상태를 기록합니다.

중요: Gemini/local LLM은 GPT-5.5가 아닙니다. 실제 fallback이 사용되거나 후보로만 준비된 경우에도 Telegram 준비 메시지와 보고에서 반드시 구분해 표시합니다.

미인증/부분 설치 복구 및 v1.6/v1.7/v1.8 승급

v1.6 또는 v1.7에서 설치했거나 업데이트했는데 답변이 없거나 자동 메시지가 오지 않는 경우를 v2.0 updater의 주요 복구/승급 대상으로 봅니다. v1.5 설치본은 cleaner 후 v2.0 installer 사용을 권장합니다.

  • PM2/npm/openclaw 런타임 누락: updater가 node, npm, pm2, openclaw, clawhub, codex 명령을 확인하고, npm이 살아 있으면 필요한 Phoenix 런타임 패키지를 다시 설치합니다.
  • 선택 인증 모드 보존: updater는 먼저 봇별 PHOENIX_MODEL_AUTH_MODE와 phoenix_model_fallback.json을 확인합니다. OpenAI/Codex 모드이면 codex login status를 확인하고 Codex CLI ChatGPT 로그인을 OpenAI provider OAuth에 import해 openai/gpt-5.5 route를 보정합니다. Gemini 선택 인증 모드이면 OpenAI/Codex 보정을 건너뛰고 Gemini provider/model 설정과 openclaw config validate --json 기준을 확인합니다. credential 값은 출력하지 않습니다.
  • OpenAI/Codex provider plugin 누락: OpenAI/Codex 모드 봇에 한해 clawhub:@openclaw/codex provider를 확인/보정해 No provider plugins found 상태를 복구합니다. Gemini 선택 인증 봇에는 이 보정을 강제하지 않습니다.
  • 잘못된 터미널 위치: 아래 프롬프트는 현재 위치가 패키지 루트인지 updater 폴더인지 먼저 확인합니다. 둘 다 아니면 멈추고 올바른 Phoenix Agent_v2.0_macOS_260706 폴더를 열라고 안내합니다.
  • PM2 등록 꼬임: 봇 PM2 프로세스가 없더라도 봇 작업 폴더의 ecosystem.config.js가 있으면 updater가 PM2 프로세스를 다시 등록합니다.
  • 재시동 복구 등록: macOS LaunchAgent ai.openclaw.phoenix.pm2.plist를 다시 등록해 로그인 후 pm2 resurrect와 준비 완료 메시지가 실행되게 합니다.
  • 답변 실패 또는 인증 만료: OpenAI/Codex 모드 봇은 같은 코딩 에이전트 내부 터미널에서 codex login으로 Codex CLI ChatGPT 로그인을 복구한 뒤 updater를 다시 실행합니다. Gemini 선택 인증 봇은 gemini_api_key.txt, gemini_model.txt, provider=google, model=google/gemini-2.5-flash 계열 설정과 openclaw config validate --json 결과를 확인합니다.

3. 봇별 기능 및 특징

Phoenix Agent v2.0_260706 봇 운영 요약

업데이트 후 기존 봇들이 어떤 기준으로 갱신되고, v2.0 자동 메시지에서 무엇을 제안하는지 정리한 섹션입니다.

v2.0은 준비 완료 알림에서 끝나지 않고, 미시작 제안, 3시간 idle 요약, 최신 트렌드 제안, 스킬 학습 안내, 실제 작업 제안, 트렌드 기반 스킬 강화 요청까지 이어집니다.

봇은 스스로 파일을 바꾸지 않고 좋은 제안을 먼저 보냅니다. 실제 스킬 반영은 마스터 승인 후 updater로 처리하여 정체성과 동작이 꼬이지 않게 운영합니다.

준비 완료PM2, Gateway, Telegram, GPT-5.5 OAuth 확인
30분 제안준비 후 시작하지 않으면 다음 작업 제안
3시간 요약무응답 시 최근 흐름과 다음 액션 정리
오전 7시봇별 최신 트렌드 검색과 작업 메뉴 제안
오전 8시좋은 샘플과 체크리스트 기반 스킬 학습 안내
오후 5시트렌드 기반 스킬 강화 요청
v2.0 자동 메시지 타입: ready_start_suggestion, idle_summary, trend_digest, skill_learning_guidance, skill_work_offer, skill_upgrade_request. 각 메시지는 봇별 역할에 맞춰 작성되며, 최신 정보가 필요한 제안은 검색 근거와 참고 링크를 함께 붙이는 기준입니다.

Phoenix Agent v2.0 PCS/PTS 스킬업

PCS: Phoenix Copy Skill

Codex Record & Replay로 실제 작업 과정을 기록하고 재현 가능한 스킬 후보로 정리합니다. 공식 기록 기준은 macOS 우선이며, Windows 사용자는 PTS를 쓰거나 검수된 macOS PCS 결과물을 가져옵니다.

PTS: Phoenix Talk Skill

Codex Skill Creator 방식으로 좋은 예시, 보고서, 페이지 구조, 영상 대본, 원고, 작업 메모를 재사용 가능한 스킬 후보로 만듭니다.

승인 원칙

봇은 스킬 후보를 제안할 수 있지만 active skill을 직접 바꾸지 않습니다. 마스터 승인 후 updater 또는 검수 절차를 통해 .agents/skills에 반영합니다.

업데이트 원칙: v1.6/v1.7/v1.8/v1.9 기존 설치본은 updater로 v2.0까지 올립니다. v1.5 설치본은 cleaner 후 v2.0 installer 사용을 권장합니다.

v2.0 24시간 Agent 운영 가이드

노트북 덮개 닫기 운영은 Phoenix Agent 소프트웨어 기능이 아니라 OS/하드웨어 설정입니다. 로컬 봇은 MacBook이 켜져 있고, 잠자기 상태가 아니며, 인터넷과 PM2/OpenClaw gateway가 살아 있을 때만 계속 동작합니다.

메뉴항목설명
1. 운영 원칙켜짐 + 인터넷 + PM2 online전원이 꺼지거나 배터리가 방전되거나 잠자기 상태가 되면 로컬 봇은 멈춥니다.
2. macOS 설정시스템 설정 > 배터리 > 전원 어댑터 / 옵션전원 어댑터 연결 시 잠자기 방지 설정을 확인합니다. macOS 버전에 따라 메뉴 이름이 조금 다를 수 있습니다.
3. 닫힌 덮개 조건전원 어댑터, 외부 디스플레이/키보드/마우스 조건MacBook은 덮개를 닫으면 기본적으로 잠자기에 들어가려는 성향이 있으므로, 장시간 운영 조건을 별도로 확인해야 합니다.
4. 선택형 도우미configure_laptop_awake_mode.commandinstaller와 updater 폴더에 각각 들어 있습니다. 현재 설정 확인, 전원 어댑터 기준 잠자기 방지 적용, 임시 keep-awake 실행 중 하나를 메뉴로 선택합니다.

방법 1. installer 폴더에서 실행

새로 설치하는 유저가 installer 폴더 안에서 실행합니다. 설치 전이나 설치 후에 현재 전원 설정을 확인하고, 필요할 때만 옵션을 적용합니다.

chmod +x ./configure_laptop_awake_mode.command 2>/dev/null || true
./configure_laptop_awake_mode.command

방법 2. updater 폴더에서 실행

기존 v1.6/v1.7/v1.8 사용자가 v2.0 updater를 실행할 때 같은 updater 폴더 안에서 실행합니다. 업데이트만 하는 유저는 이 방법을 쓰면 됩니다.

chmod +x ./configure_laptop_awake_mode.command 2>/dev/null || true
./configure_laptop_awake_mode.command

방법 3. Genesis Bot에게 지시해서 진행

명령어가 부담스러운 유저는 Genesis Bot에게 아래 지시문을 보내면 됩니다. Genesis Bot은 먼저 확인만 하고, OS 설정을 바꾸기 전에는 무엇을 바꿀지 보고하고 승인받아야 합니다.

Genesis Bot, Phoenix Agent v2.0 24시간 Agent 운영 설정을 도와줘.

목표:
- MacBook 덮개를 닫아도 봇이 계속 돌 수 있는지 확인
- 전원 어댑터/잠자기/pmset 상태 확인
- installer 또는 updater 폴더 안의 configure_laptop_awake_mode.command 파일을 찾아 먼저 현재 설정만 확인
- 토큰/API Key/OAuth 값은 절대 출력하지 말 것
- sudo나 OS 설정 변경이 필요하면 먼저 무엇을 바꿀지 보고하고 내 승인을 받을 것

먼저 현재 폴더 위치와 도우미 파일 존재 여부를 확인하고, 실행 가능한 방법을 짧게 보고해줘.
중요: 이 기능은 봇 자체 기능이 아니라 macOS 전원 설정과 MacBook 하드웨어 상태가 함께 맞아야 동작합니다. 전원 OFF, 배터리 방전, 인터넷 끊김 상태에서는 로컬 봇이 계속 활동할 수 없습니다.
